# Hyra 1.0 与 2.0 对照：解题范式 vs 工具范式

**一句话结论**：1.0 把「一个循环把分数刷上去」做到极简，2.0 把同一批 agent 组织成一支能跑数周、多项目并行的研发队伍。两者不是同一设计的版本递增，而是**产出单位**的变化——从「一个更好的 solution」变成「一个能被复用的工具」（[[hyra-1-0]]；[[hyra-2-0]], section "从答案到工具"，`raw/articles/Hyra 2.0.md:40-42`）。

## 对照表

| 维度 | Hyra 1.0 | Hyra 2.0 |
| --- | --- | --- |
| 定位 | 通用科研 agent 的极简循环（[[hyra-1-0]], section "Hyra Harness"） | 参与研发与升级科学模型/工作流/软件工具（[[hyra-2-0]], `:57-59`） |
| 产出单位 | 更优 solution（含 `solve.sh` 的 `solution/`） | 科学模型、证明工作流、验证系统、机械结构、芯片优化 |
| 单轮时间尺度 | 一次沙盒运行 | 数天到数周的项目（`:63`） |
| 组织结构 | Context Agent + 多个 Proposal Agent + 信号量 | Overall / Mission / Worker 三层 + Review Worker（`:67`、`:77`） |
| 调度 | 异步生产者-消费者，追求资源满载 | 持久化队列、优先级/依赖/资源上限、agent 自设唤醒时间（`:69`） |
| 协作记录 | 经验库 EB + 灵感队列 | Research Board（想法/发现/证据/决策）+ 队列（`:71`） |
| 记忆 | EB 单一结构，按任务 | 项目状态 / agent 分层记忆 / 跨任务 Books（`:81`） |
| 可信度机制 | 无显式分级，高分即优质 | 观察 / 已验证（需独立复现）/ 约定（需人类确认）（`:83`） |
| 验证方式 | 评估器 + reward hacking 事后发现（[[hyra-1-0]], `Hyra.md:55`） | 证据随报告提交、Mission 核查、独立复核、形式化验证与精确证明（`:77`、`:165`） |
| 人工介入 | 未描述 | 大算力开销与共享知识同步需审批（`:65`） |
| 结果形态 | 榜单/纪录刷新（BPB、kernel SOL、数学纪录、Botzone 名次） | 端到端工件（新模型、新码、新手、芯片改动） |
| 基座模型 | 明确为 Hy3 | **未披露** |
| 证据强度 | 厂商自评，无脚本 | 厂商自评；7 图 1 视频已目视核查并读到具体数值（2,532 designs/s、131k residues/s、MAE 区间等），部分结果对照公开榜单/issue 列表，仍无技术报告 |

## 什么变了

1. **harness 从「循环」变成「组织」**：1.0 的设计要点是尽量轻、动作空间尽量大；2.0 承认工具研发「很难靠一个不断延长的 agent session 来管理」，于是引入角色分工、持久化队列与审批门（`:63-65`）。可复用的部分仍是「让 agent 直接读代码、跑实验、改代码」的宽广动作空间。
2. **验证从补丁变成制度**：1.0 是在作弊被发现后主张「eval 必须进入研究循环」；2.0 直接把证据提交、独立复核与知识分级写进流程。这是本对照里最实质的进步（对比 [[evaluator-design-and-reward-hacking]]）。
3. **经验复用的抽象层级上移**：EB 复用「某次 solution 的上下文」，2.0 复用「带适用条件的方法」，并进一步封装为 skill（[[research-memory-tiers]]）。
4. **失败的解释方式变了**：1.0 的叙事是「刷分」；2.0 把未解问题转成瓶颈分类（模型能力 / 搜索效率 / 验证反馈太慢），再作为下一轮工具研发目标（`:187`）。

## 什么没变

- **仍是厂商自评**：两篇都没有论文、评测脚本、算力预算与第三方复现；对比数字只能作为「作者声称」使用。
- **仍以可自动判定的信号为基础**：2.0 的数学、量子码、芯片工作之所以能做，前提仍是存在客观判据（证明核验、码距、SPEC 分数、fuzzer 与 TLA+ 反例）。
- **仍回避归因**：两篇都未做消融，无法区分「harness/流程贡献」与「底层模型换代贡献」；2.0 甚至未说明所用模型。
- 本库对 2.0 的图片与视频已目视核查（2026-11-11，临时文件未入库），但读图只能确认「图里写了什么」，不能替代原始数据与评测协议。

## 怎么读这两篇（建议）

1. 想借鉴**单任务搜索循环**的工程细节（沙盒、灵感、双层评估器）→ 读 [[hyra-1-0]] 与 [[research-agent-harness]] 的 1.0 部分。
2. 想借鉴**长周期多项目管理**（队列、看板、审批、复核）→ 直接读 [[hyra-2-0]] 的 Harness 一节与 [[research-agent-harness]] 的 2.0 部分。
3. 关心**结果可信度**→ 先读本页「什么没变」，再用 [[hyra-2-0]] 的局限一节逐条核对具体数字的条件。
4. 关心**范式主张**（为什么造工具优于刷分）→ 读 [[tool-centric-research]]；注意该主张目前只有机制论证，没有复用率数据。
