# AIDE 脚手架（aideml）：把 MLE 当作代码空间的树搜索脚手架

Weco AI 的 AIDE（AI-Driven Exploration）是一个面向机器学习工程的开源脚手架：把「写脚本、跑实验、看分数」的试错过程组织成代码解空间上的树搜索（来源：[[aide]], p. 1、p. 3）。仓库地址 <https://github.com/WecoAI/aideml>（p. 1，2024-04 开源，p. 2）。本页只覆盖论文所描述的设计与报告结果；**仓库内部实现是否与论文一致未核查**。

## 架构（来源论述）

| 组件 | 符号 | 做法 | 出处 |
| --- | --- | --- | --- |
| 解 | `s ∈ S` | 一个可独立运行的单文件 Python 脚本；`s₀` 为空脚本 | p. 3 |
| 评估器 | `h : S → R` | 无状态标量打分（验证指标） | p. 2 |
| 解树 | `T` | 节点 =（脚本, 分数），边 = 一次改进尝试 | p. 3 |
| 搜索策略 | `π(T)` | 硬编码：draft 补足初始解 → debug 未超深度的 bug 节点 → 否则 improve 最好的非 bug 解 | p. 3 |
| 编码算子 | `f(s, Σ(T))` | 三个入口：draft（先方案后单文件代码）、debug（保留思路修错误）、improve（**只做一处原子改动**） | p. 3–4 |
| 摘要算子 | `Σ(T)` | 只回填性能指标、超参设置、调试线索；让节点「无状态」但继承先验 | p. 4 |
| 数据预览 | — | 把行数、列名、划分等元数据插进 prompt；非完整 EDA | p. 4 |

算法骨架（p. 3，算法 1）：`sₙ ← f(s, Σ(Tₙ₋₁))` → `vₙ ← h(sₙ)` → 挂到树上 → `s ← π(Tₙ)`；预算耗尽后返回历史最优解 `argmax h(s′)`。

## 契约与环境（论文能确认的部分）

- **产物**：要求产出 `submission.csv`，模仿人类选手提交流程；在 Weco-Kaggle 协议中，AIDE 可见 holdout 的输入但不可见标签（p. 5）。
- **评测单位**：单个节点独立评测，节点分数就是后续选点的依据（p. 3–4）。
- **时间预算**：MLE-Bench 跑在 24 小时窗口内并持续精修部分解（p. 8）；Weco-Kaggle Lite 的一次运行未报时长与步数上限；Fig 6 的横轴到 18 步，可作迭代规模参考（p. 15，已目视核查）。
- **未公开**：初始解数量、调试深度上限、总步数、每节点时限、采样温度、prompt 全文、沙箱与资源限制——论文均无数值（见 [[aide]] 的「局限」）。想复现只能读仓库，不能靠论文。

## 作为基线怎么用（综合）

1. **当「便宜且可审计」的参照实现**：开源 + 单文件脚本 + 显式解树，比通用 agent（ReAct 式）更容易复盘每一步改了什么、为什么分数变了。
2. **固定契约后再比**：若要用它评测自己的方案，至少对齐（a）数据切分与 holdout 是否对 agent 隐藏标签、（b）单次提交次数与迭代预算、（c）指标是分位（`Exceeds % of Humans`）还是奖牌计数。作者选分位的理由是可跨竞赛平均且细粒度（p. 5）。
3. **把它当作「原子改动的上限试验」**：AIDE 的 improve 每次只改一处，因此可以拿它来检验「我的多改动方案是否真的比单步改进更好归因」。
4. **不要直接外推到长程任务**：RE-Bench 上 AIDE 在需要大代码库改动或多步交互的任务里反复打局部补丁（p. 9）。

## 报告的结果（摘要）

| 基准 | 结果 | 口径 |
| --- | --- | --- |
| Weco-Kaggle Lite（16 竞赛） | Exceeds 51.38%、Above Median 50% | GPT-4 Turbo，2024-02 手工提交（p. 5–6） |
| 完整 Weco-Kaggle | Exceeds 48.23%、Above Median 49.21% | 63 个竞赛（附录实列 80 行，见 [[aide]] 分歧） |
| MLE-Bench（第三方） | 任意奖牌 16.9 ± 1.1%、金 9.4 ± 0.8% | AIDE+o1-preview，16 种子（p. 7） |
| MLE-Bench Lite | 任意奖牌 7.6→36.4%、Above Median 13.6→59.1% | 加 AIDE 前后，p<0.01（p. 8） |
| RE-Bench（第三方） | 6 小时窗口内平均分超人类；Kernel 任务快于 9 位专家（64h 预算） | 人类随后反超（p. 9） |
| 成本 | 单任务 LLM 推理最高 ≈$2.50、多数 <$1.50 | GPT-4 Turbo 2024-01/02 定价（p. 13、p. 15） |

全部数字的完整条件见 [[aide]]「结果数字一览」。注意 MLE-Bench 的「4 倍于 OpenHands」是跨模型比较，同模型（GPT-4o）约为 2 倍（p. 2、p. 7、p. 9）。

## 使用边界

- **适用**：目标可用标量指标评估、解能写成单文件脚本、单次运行分钟级到小时级的 Kaggle 类任务；代码即产物的工程任务（kernel 优化、小型 NAS、微调 recipe）。
- **慎用**：评估器不可靠或可被绕过的场景（AIDE 没有内置的作弊检测，只有 holdout 隐藏标签这一层保护，p. 5）；需要跨文件重构、依赖大量交互步骤的任务（p. 9）。
- **版本风险**：论文是 2025-02 的快照，仓库此后可能变化；本页不承诺仓库当前行为。`verified: 2026-11-11` 仅指「本页与论文快照一致」。

## 与其它 harness 的关系

AIDE 是「树搜索 harness」的公开参照，其余四种形态见 [[research-agent-harness]]：Hyra-1.0 用经验库 + 灵感队列 + 异步生产者/消费者（[[hyra-1-0]]），Hyra 2.0 用多项目长周期组织（[[hyra-2-0]]），AlphaEvolve 用进化式程序数据库（[[alphaevolve]]），autoresearch 用单文件贪心 + 人类维护的指令文件（[[autoresearch]]）。五种形态的共同点是「生成—评估—保留」，差别在记忆载体与验证制度。
