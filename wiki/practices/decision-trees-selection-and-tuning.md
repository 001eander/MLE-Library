# 决策树的选型与调参

工程指导页。机制与推导见 [[decision-trees]]，来源证据见 [[sklearn-decision-trees]]。引用写作 `[[sklearn-decision-trees]], L218`。

> [!warning] 版本前提
> 本页参数语义按**官方 1.9.1** 核对；标「实测」的条目是在本机 **scikit-learn 1.6.1** 上跑出来的（PyPI 当前可安装的最高版本）。凡是行为随版本变化的条目（MAE 的成本、哪些准则支持缺失值、`friedman_mse` 的状态）都单独标注。

## 一、先判「该不该用」：树擅长的四件事与不擅长的四件事

来源没有给选型指南，只给了一列优势与一列劣势（L16–L34）。把它们翻译成判据：

| 场景 | 树是否合适 | 依据 |
| --- | --- | --- |
| 特征量纲混杂、缺失值多、不想做插补 | **合适**（唯一原生支持缺失值的族） | L19、L318–L366 |
| 需要给非技术方看"为什么" | **合适**（可画树、可导文本） | L18、L79–L127 |
| 交互/非线性的**粗**基线，先探有没有信号 | **合适**（不需要缩放、不需要特征工程） | L19 |
| 目标可能超出训练范围（外推、趋势预测） | **不合适**：叶子输出是训练样本统计量 | L31 |
| 边界本身是平滑/斜的（如线性可分但旋转过） | **不合适**：只能轴对齐 | L10、L237 |
| 概念是 XOR / parity / 多路复用 | **不合适**（单特征切分表达不了） | L33 |
| 类别极不平衡 | **需先处理**（否则树偏向多数类） | L34、L222 |
| 需要可信概率 | **需后处理**（叶内比例不是校准概率） | L59 |

另外一条只有经验才能给的判断（**本库综合**）：树很少是终点。它的不稳定（L30）与"深层必然过拟合"（L29）决定了它在实践里多数时候是**集成（RF/GBDT）的基学习器**，而不是最终模型。单独用树的最常见理由是可解释性，不是精度。

## 二、第一步永远是可视化，而不是调参

来源的建议很具体：**训练时就把树画出来，先 `max_depth=3` 看清拟合形态，再逐级加深**（L218）。

可执行的顺序：

1. `DecisionTreeClassifier(max_depth=3).fit(...)`，用 `plot_tree`（L79）或 `export_text`（L111）看前 3 层切的是哪些特征、阈值落在哪里。
2. 检查三件事：**切分是否落在业务上可解释的位置**、**叶子是否已经被单一类别占满**、**有没有特征被反复使用**。
3. 再放开到 `max_depth=5` 或直接 `None` + `ccp_alpha`（见第四节），比较验证分数。

**易踩的坑**：`export_text` 在剪藏里只有代码没有解释（折叠块丢失），它是**不需要 graphviz 的纯文本导出**（外部核查）；但它的 `max_depth` 参数默认 `None` 会打印整棵树——大树会把日志打爆。

## 三、前剪枝：五个旋钮，先动两个

前剪枝旋钮在**长树的过程中**生效，默认值来自 1.9.1 API 页（外部核查）：

| 旋钮 | 默认 | 起点建议 | 语义要点 |
| --- | --- | --- | --- |
| `max_depth` | `None` | **`3`**（来源明说，L218） | 每加一层，需要的样本数翻倍（L219） |
| `min_samples_leaf` | `1` | **`5`**（来源建议，L220）；分类且类别少时 `1` 常常最好（L220） | 保证每个叶子有多个样本支撑；回归里避免低方差叶子（L220） |
| `min_samples_split` | `2` | 一般不动 | **不保证叶子大小**，只控制父节点（L220）；**按未加权样本数算**（L221） |
| `min_impurity_decrease` | `0.0` | 视需要 | 切分收益低于它就停（L266） |
| `min_weight_fraction_leaf` | `0.0` | 有 `sample_weight` 时用它 | 叶子至少占整体权重的一个比例（L223） |
| `max_leaf_nodes` | `None` | 想直接控"树宽"时 | 与 `max_depth` 是两种不同的预算（外部核查） |

两条来源明确点出的取舍：

- **`min_samples_split` vs `min_samples_leaf`**：前者可能造出任意小的叶子，后者保证叶子下界（L220）。回归里优先后者。
- **权重场景要换准则**：`min_samples_split`/`min_samples_leaf` 不看权重，所以样本加权后它们会**偏向多数类**；`min_weight_fraction_leaf` 才看权重（L221、L223）。

**本库综合**：`max_depth` 与 `min_samples_leaf` 联合起来大约等价于"最多 $2^{d}$ 个盒子、每盒至少 $k$ 个样本"，因此"深度预算"和"叶子预算"不该同时扫——会得到一片几乎相同的验证曲线，浪费网格。

## 四、后剪枝：`ccp_alpha` 是唯一带单位正负号的旋钮

来源给的最小代价复杂度剪枝（L368–L378）：

$$R_\alpha(T)=R(T)+\alpha\,|\tilde T|,\qquad \alpha_{\text{eff}}(t)=\frac{R(t)-R(T_t)}{|T|-1}$$

`ccp_alpha` 默认 `0.0`（不剪枝，外部核查）。推荐写法：

1. `path = clf.cost_complexity_pruning_path(X, y)` 取整条 $\alpha$ 序列（外部核查：剪藏未提该 API）；
2. 对 `path.ccp_alphas` 的**子集**（不是全量，通常几十个点足够）做交叉验证；
3. 用验证分数选 $\alpha$，再在全量训练集上重拟合。

三个注意点：

- **`R(T)` 用的是加权不纯度而不是误分类率**（L376）。所以 `ccp_alpha` 的尺度与 `criterion` 绑定：换成 `entropy` 后同一个 $\alpha$ 的强度会变。
- **后剪枝不省训练时间**：它先长满再剪（L368–L378），比前剪枝贵。
- **`ccp_alpha` 与前剪枝会交互**：如果先用 `max_depth=5` 限制了树，再扫 $\alpha$，$\alpha$ 的可选范围被压窄。

## 五、类别不平衡与权重：两个入口，一个副作用

来源给了两种平衡方式（L222）：等量重采样，或者**把每类的 `sample_weight` 之和归一化到同一值**（后者被明确推荐）。参数层面还有 `class_weight`（外部核查：1.9.1 签名有，剪藏 grep 为 0）。

**实测（1.6.1）的副作用**：`predict_proba` 是**加权**比例。三个样本 `y=[0,1,1]` 不可分时，默认 `predict_proba=[[0.333, 0.667]]`，`class_weight='balanced'` 后变成 `[[0.5, 0.5]]`。

**含义**：类别平衡不但改决策边界，还改概率数值。如果下游要用概率（阈值选择、期望收益），先固定权重再校准，不要在两套权重下比较概率。

## 六、缺失值：可以直接喂 NaN，但要知道它学了什么

能直接喂（L318–L366），前提是：

| 条件 | 说明 |
| --- | --- |
| 估计器 | `DecisionTree*` 用 `splitter='best'`；`ExtraTree*` 用 `splitter='random'` |
| 训练机制 | 每个阈值评估"NaN 全左 / 全右"两种（L324）；ExtraTree 随机分（L361） |
| 预测规则 1 | 按训练学到的方向（L328） |
| 预测规则 2 | 平票 → **走右**（L338；实测复现） |
| 预测规则 3 | 训练未见 NaN 的特征 → 走**样本更多**的子节点（L349；实测复现） |
| 准则覆盖 | **随版本变化**：1.9 起 `absolute_error` 也支持稠密 NaN；1.8 页曾有准则清单，1.9 页删除（外部核查） |

**工程建议（本库判断）**：

1. 规则 3 是**与特征值无关**的默认方向，等于一个"永远偏向多数分支"的隐式插补。如果缺失比例高且与标签相关，这个默认会制造难以察觉的偏差——**要么显式插补，要么把缺失做成指示特征**。
2. 不要在 Pipeline 里"先插补再喂树"还期待等价结果：插补会把 NaN 变成真实数值，树就失去了"每个阈值学方向"的能力。
3. 稀疏输入时：`fit` 前转 `csc_matrix`、`predict` 前转 `csr_matrix`（L225；来源说训练可能快几个数量级）。

## 七、数据类型：float32 不是细节

来源明确说：**所有决策树内部都用 `np.float32` 数组，输入不是这个格式就会复制一份**（L224）。

**实测（1.6.1）的后果**：`X = [0, 0.30000001, 0.30000002, 1]` 在 float32 下塌成 `[0, 0.3, 0.3, 1]`——两个不同的 float64 值变成同一个阈值候选，树只切出 3 个叶子（本应 4 个），在 `0.300000015` 处的预测变成两个目标值的平均 `1.5`。另一处可见证据：阈值被存成 `0.25000001`、`0.65000001`，而不是 0.25、0.65。

**什么时候要在意**：

- 特征本身是**高精度测量值**（时间戳、金额、传感器读数），且相邻取值差异小于 float32 的相对精度（约 $10^{-7}$）；
- 需要**与 float64 训练的其他模型做逐阈值对比**（比如复现别人的树结构）。

处理方式：先 `X.astype(np.float32)` 自己转一次（避免静默复制，也让"阈值会被舍入"这件事在代码里可见），或者把高精度特征做差分/取对数后再用。

## 八、`random_state` 与可复现性

- `splitter='random'`（含 `ExtraTree*`）**必须**设 `random_state`，否则每次切分不同（L258、L260）。
- `random_state` 对 `splitter='best'` 的**平票**是否有影响：本机在 iris 上试了 `None/0/1/2/3` 五个取值，全树根切分完全相同（`X[3] <= 0.8`，9 叶、深度 5）。因此**不要把树结构的差异默认归因于 `random_state`**；先怀疑数据顺序、dtype 或版本。
- `predict` 的平票**不随机**：取 `classes_` 中索引最小的类（L57；实测 `y=['b','a']` → 返回 `'a'`）。所以**重编码标签会改预测**。

## 九、坑清单（按"踩到才发现"排序）

1. **默认就是"长到纯"**：`max_depth=None`、`min_samples_leaf=1`、`ccp_alpha=0.0`，不加限制的训练集准确率必然接近 100%（L29 + 外部核查）。
2. **`min_samples_split` 不数权重**（L221，实测确认）。加权后以为"叶子够大了"，其实没有。
3. **`min_samples_split` 不保证叶子大小**（L220）——1 个样本的叶子合法。
4. **`ExtraTree*` 的 `max_features` 默认不是 `None`**：分类 `'sqrt'`、回归 `1.0`（外部核查）；而 `DecisionTree*` 是 `None`。同一份数据上实测：`DecisionTreeClassifier` 13 叶，`ExtraTreeClassifier` 79 叶——差异主要来自这个默认值，不是"ExtraTree 更随机"这么简单。
5. **`predict_proba` 是叶内（加权）比例**（L59 + 实测），不校准直接用会高估置信度。
6. **`predict_proba` 在加权后会变**（实测 `class_weight='balanced'` → `[0.5, 0.5]`）。
7. **平票取最小索引**（L57，实测）——标签编码改变预测。
8. **float32 会吞掉相邻值**（L224，实测：两个值塌成一个，少一个叶子）。
9. **缺失值的"未见 NaN"分支走多数子节点**（L349，实测）——部署漂移下的隐式偏差。
10. **`poisson` 要求 $y\ge0$**（L308，实测报 `ValueError`）。
11. **MAE 的成本口径随版本变**：文档说 1.8 起是 MSE 的 3–6×（L316）；本机 1.6.1 实测 ≈23×。跨版本引用这个数字会错一个数量级（来源页有版本史）。
12. **`iris.svg` 那张官方图是 2014 年的静态资产，根切分与当前实现不同**（petal length ≤ 2.45 vs petal width ≤ 0.80）。抄图里的阈值前先自己跑一遍。
13. **`friedman_mse` 在 1.9 已弃用**（外部核查），本节也不再列它；旧代码里的 `criterion='friedman_mse'` 应改成 `'squared_error'`。
14. **`export_text` 默认打印整棵树**（`max_depth=None`），大树会把 notebook/日志撑爆。

## 十、对智能体的可自动化程度

| 步骤 | 可自动化 | 说明 |
| --- | --- | --- |
| 前剪枝网格（`max_depth` × `min_samples_leaf`） | **高** | 离散、低维、单次拟合便宜 |
| `ccp_alpha` 路径 + CV | **高**（需要额外 API） | `cost_complexity_pruning_path` 一次给出路径；剪藏未提，需自行实现 |
| 缺失值"喂 NaN vs 插补"的 A/B | 中 | 需要两套 Pipeline 与同一 CV 划分，容易比较不公平 |
| 可视化与阈值审查 | **低** | 需要人判断"切分是否业务上说得通" |
| `predict_proba` 校准 | 中 | 需要 `sklearn.calibration`（未入库） |
| 特征重要性解释 | 低 | 本节不覆盖；impurity-based 重要性有已知偏置，需读 5.2（未入库） |

## 待解问题

1. `min_impurity_decrease` 的合适量级：它依赖不纯度的尺度（Gini vs entropy），文档没有给单位或示例。
2. `ccp_alpha` 的 $\alpha$ 在样本加权下是否随权重尺度变化（因为 $R(T)$ 是加权不纯度）。
3. 缺失值 + 权重 + `min_weight_fraction_leaf` 三者叠加时的行为（文档分开讲，没有组合示例）。
4. 树在多输出回归中，各输出量纲差异是否需要先标准化。
5. 前剪枝与 `ccp_alpha` 同时使用时的推荐顺序（本页建议先前剪枝定粗结构、再扫 $\alpha$，但**未验证**）。
6. 本机 1.6.1 与文档 1.9.1 的行为差：`absolute_error` + NaN、`monotonic_cst` + NaN 都只在 1.9 起支持，未实测。
