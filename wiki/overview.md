# MLE Library

由 Pi 图书馆员在人工监督下维护的个人机器学习工程知识库。

## 用途

- 学习新的机器学习工程概念，并复习实用指导。
- 为 MLE AutoResearch Agent 提供对精选知识和来源证据的只读访问。

## 分层结构

- `raw/` 保存不可变的来源材料。PDF、剪藏文章和原始资产绝不在原处编辑。
- `wiki/` 保存由图书馆员维护的 Markdown 页面。重要论述会链接到来源页面和精确的来源位置。
- `AGENTS.md` 和 `.agents/skills/` 定义图书馆员如何收录、查询、维护和提交知识。

从 [[index|知识索引]] 开始。主题页面位于 `concepts/`，工程指导位于 `practices/`，特定工具的笔记位于 `tools/`，来源摘要位于 `sources/`。研究草稿保留在 `research/`，直到有人决定将其提升为稳定知识。

把它推进到多项目长周期的工具研发，并新增分层记忆与知识分级。Kaggle 入门指南是唯一以**人类选手**为对象的来源，描述七段竞赛流程与人类如何判断自己的改进是否可信，为前五个智能体来源提供了评估尺度的另一侧；scikit-learn 文档则是第一个「工具行为」类来源，给出现行 API 的估计器矩阵、默认值与求解器约束（同时它是一份残缺的剪藏，见该页的转换损失专节）；1.2 节 LDA/QDA 把同一套工具页从判别式模型扩展到**生成式**模型，并第一次给出可量化的协方差收缩证据（小样本下不收缩直接失效）；1.9 节 Naive Bayes 再把生成式一侧扩到**条件独立**分支，并给出本库第一条「分类器好、概率估计量坏」的警告（该剪藏在所有者授权下回填了 21.4% 的缺失内容，见该页的转换损失专节）；1.4 节 SVM 补齐第五个模型族（从**几何间隔**出发，而非损失或分布），也是本库**第一次把算力规模写成选型依据**的来源，并给出了“分数 vs 概率”的第一条具体校准路径——而这条路径在 1.9 已被弃用（文档与 API 错位，见该页的分歧节；该剪藏回填了 19.0% 的缺失内容）；1.6 节 Nearest Neighbors 补上第六个模型族，也是本库**第一个零参数、非泛化**的族——「模型」就是训练集，因此「训练」只是建索引、推理成本随 $N$ 增长；它同时是本库第一处能把「实现选择」与「模型选择」彻底分开的地方（三种搜索结构算同一个数学对象，选错只慢不错），并带来第一个「学度量」的算法（NCA ＝ 学一个 Mahalanobis 度量）。1.10 节 Decision Trees 补上第七个模型族，也是本库**第一个「模型 = 一组 if-then-else 规则」**的族：分段常数 + 轴对齐递归划分，容量不是靠惩罚项而是在拟合前由结构旋钮锁定（深度/叶子大小），并带来第一个**原生支持缺失值**的模型与第一个**罚模型结构**的正则项（代价复杂度剪枝，罚的是叶子数）；它也是本库第一份把「算法最优性」（NP-complete → 贪心）与「工程不稳定性」直接挂上因果的来源。1.11 节 Ensembles 是第七个 sklearn 文档来源，也是本库第一个「**组合策略**」类目（而不是又一个模型族）：它把前面各节的模型当作基学习器，用平均（随机森林/Extra-Trees/Voting/Stacking）买降方差、用顺序纠错（GBDT/HGBT/AdaBoost）买降偏差；第一次把「计算预算」写成一等公民（直方图分箱把单节点切分从 $O(n_f n\log n)$ 降到 $O(n_f n)$），第一次出现「同一族三套实现连支持的功能都不同」（HGBT 原生缺失值/类别/单调与交互约束，`GradientBoosting*` 都没有），也第一次出现「元学习器」（Stacking 用折外预测训练第二层，使 CV 从评估手段变成训练机制）。该剪藏丢了 **8 个折叠块 + 1 个 `aside` + 整个 1.11.4.1 节（≈1,750 词 ≈ 21%）**，正好是 GBDT 数学、损失表、「小样本应优先用旧实现」与硬投票平票规则；20 条文献只剩 1 条。已在来源页逐块记录，并在本机 1.6.1 实测了 10 条运行时行为（早停 100→76 轮、硬投票平票取升序、RF 概率平均差 0.0、`max_bins=256` 报错等），版本判为 1.9.1。该剪藏的 3 个内容折叠块全部丢失（530 词散文，正好是导出树、ID3/C4.5/C5.0 谱系、熵=log loss 的推导），已在来源页逐句记录；版本可判定为 1.9.1（1.8→1.9 有两处文本改动），另在本机 1.6.1 实测了 10 条运行时规则，并发现官方 `iris.svg` 是 2014 年的陈旧资产（四个版本字节相同，根切分与同页 doctest 不一致）。该剪藏的选型内容约 20% 丢失（6 个折叠块只剩 1 个），丢失部分已按官方 1.9 页核实并标注，另在本机 scikit-learn 1.6.1 上实测了 6 条运行时规则（见该页转换损失 E 节）。1.13 节 Feature selection 补上本库**第一个「选择」类目**（不是又一个模型族）：它不引入新的假设形式，而是在拟合前**删列**。一页里三个家族齐备但文档从不点名：过滤式（`VarianceThreshold`、`SelectKBest`/`SelectPercentile`/`SelectFpr`/`SelectFdr`/`SelectFwe`）、包裹式（`RFE`/`RFECV`/`SequentialFeatureSelector`）、嵌入式（`SelectFromModel` + L1 或 MDI）。它第一次把「正则化」与「选列」接上（$C$ 越小、`alpha` 越大 → 特征越少，L119），也是本库**唯一明文推荐把某一步放进 `Pipeline`** 的来源（L163–L173，虽不给理由）；本机实测把理由量化了：120 样本 × 20,000 个纯噪声特征，选择放进管线时 5 折 CV = 0.508（机会水平），先在全量数据上选择再 CV = **0.900**。该剪藏丢了 **1 个 `aside` + 2 个 `<details>` + 整段 References（386 词 ≈ 19%）**，丢的恰好是「稀疏输入不被稠密化」「Lasso 精确恢复支撑集的条件」「前向/后向的成本算术」；版本判为 1.9.1（四道 1.6→1.9 措辞判据），另在 1.6.1 实测 16 条（`SelectFromModel` 的默认阈值在 L1 与树上是两套语义、`GenericUnivariateSelect()` 默认只留 1 列、`SelectFpr(alpha=0.05)` 在 200 维噪声上留 11 列、`prefit=True` 下读 `threshold_` 报 `AttributeError`）。1.17 节 Neural network models 补上本库**第一个参数化、非凸、随机初始化**的模型族（[[multi-layer-perceptron]]）：MLP 分类/回归、`coefs_`/`intercepts_` 的按层索引、logistic/softmax/identity 三个输出面、SGD/Adam/L-BFGS 三种训练契约（只有前两者有 `partial_fit`），以及 `alpha` 的 $ℓ_2$ 只罚权重矩阵不罚偏置。它也是本库**第一份「剪藏保留接口、丢掉全部为什么」的极端样本**：3 个内容折叠块全丢（622 词 ≈ 36%），正好是非凸/局部极小/随机初始化、完整损失与反向传播、5 条文献；版本判为 **1.8.0–1.9.1**（四条判据：三处排除 1.6、一处排除 1.7；1.8→1.9 正文无 diff，取 `/stable/` 1.9.1），并在 1.6.1 实测 15 条（8 个种子准确率 0.9367–0.9533、`alpha` 从 $10^{-5}$ 到 $10$ 使权重范数 100.66→1.97、L-BFGS 无 `partial_fit`、早停 395→34 轮、缩放 0.788→0.889）；另发现 **1.7 起 `MLPRegressor` 已有 `loss='poisson'` 而正文只说平方误差**。五种 harness 形态的对照见 [[research-agent-harness]]，搜索与记忆机制的概念页为 [[code-space-search]]，Hyra 两代差异见 [[hyra-1-0-vs-2-0]]，线性与生成式基线的工程用法见 [[linear-models-as-baselines]]，判别分析的几何与参数代价见 [[nearest-neighbors-selection-and-tuning]]；决策树的机制见 [[decision-trees]]、选型与调参见 [[decision-trees-selection-and-tuning]]；集成的机制（两条轴、函数空间梯度、折外预测）见 [[ensembles]]、选型与调参见 [[ensembles-selection-and-tuning]]；特征选择的机制（三家族、代理指标、成本与方差）见 [[feature-selection]]、落地流程与 16 条坑见 [[feature-selection-workflow]]；MLP 的机制（非凸优化、三个输出面、三个求解器）见 [[multi-layer-perceptron]]、选型与调参见 [[mlp-selection-and-tuning]]。2.2 节 Manifold learning 是本库**第一个「没有 $y$、输出一套坐标」**的类目，也是目前**结构最完整**的一份剪藏（14 条文献全在、散文逐句对齐，只丢了 10 个折叠块的数学与 1 张图）：它把「降维」从「删列」（1.13 节）推进到「换坐标」，并把选型的第一性判据从方法名换成**被保量**（测地距离 / 局部重构权重 / 图上邻近 / 内积 / 不相似度的序 / 邻域概率）。它同时贡献了本库几个「第一次」——第一次把「官方自己的图否证官方自己的正文」记录在案（L90 称 HLLE 成本与其他 LLE 变体相当，而图标题是 0.187s vs 1.811s）、第一次出现「同一个小节里 `stress_` 有三种量纲」、以及第一次用本库自建的**全局保真度**指标把「t-SNE 全局差、`init='pca'` 缓解」从断言变成读数（0.5141 → 0.6201，而 PCA 是 0.6456）。版本判为 **1.8.0–1.9.1**（82 条句子探针 61/68/75/75，并含 1.8 新增的 `ClassicalMDS` 段；1.8→1.9 正文无 diff），另在 1.6.1 实测 15 条（缩放使 Isomap 局部保真度 0.5029→0.8952、`SpectralEmbedding.n_neighbors=None` 等价 $n/10$、`MDS.n_init` 1 与 4 对应 stress 431 与 419、`arpack` 的奇异失败可复现而「重复点」不可复现）。2.3 节 Clustering 是本库**第一个「无监督、输出标签」**的类目，也是**第一个自带评估指标的 sklearn 章节**：它把无监督产物补全为三种——删列（1.13）、换坐标（2.2）、**分组**（2.3）——并把选型轴从「方法名」换成**几何假设**（inertia 的凸+各向同性、密度连通、图割、Ward 方差），同一份数据在四种假设下有四个不同的正确答案。它同时贡献了本库几个「第一次」：第一次出现「归纳 vs 传导」硬断层（`SpectralClustering`/`AgglomerativeClustering`/`DBSCAN`/`HDBSCAN`/`OPTICS` 都没有 `predict`，不能上线）；第一次把「$k$ 从哪来」写成三种模式（显式 `n_clusters` / `eps`-`min_cluster_size` 间接决定 / `preference`-`bandwidth` 自定）；第一次给出指标的三个可判定性质（置换不变、机会校正、对称），从而能判定「哪个指标可以回答『比随机好多少』」（只有 ARI/AMI）与「哪个能当共识度量」（只有对称的那几个）。该剪藏是本库**结构损失最大**的一份：**30 个内容折叠块全丢（3,073 词 ≈ 24%）、16 个 References 块全空、总览表的第一列（方法名）整列丢失**——丢的正好是 4 个数学表述、AP 与 BIRCH 的算法描述、DBSCAN 的 `Implementation`（边界点顺序依赖！）与内存节、OPTICS 的复杂度、BIRCH 的三个用法问答；版本判为 **1.9.1**（126 条句子探针 107/108/110/111，剪藏含 1.9 才改的 "assigning"；`/stable/` 与 `/1.9/` 字节相同、页脚 1.9.1），另在 1.6.1 实测 20 条（`n_init='auto'` 只跑一次 → inertia 32.77±2.06 vs 30.21±0.19、`tol` 按数据方差归一因而尺度不变、DBSCAN 边界点顺序依赖可复现、`eps` 0.05→全噪声而 10→单簇、`cluster_optics_dbscan(0.5)` 与 `DBSCAN(0.5)` 在 iris 上完全一致、`Birch()` 默认 3 簇而 `n_clusters=None` 给 13 个子簇、`discretize` 吃 `random_state` 故「100% 可复现」不成立、MiniBatch 快 3–24× 但 inertia 差 3.8–5.4%、`v_measure_score` ≡ NMI(arithmetic)），并发现**剪藏的 AMI doctest 是 0.22 之前的旧口径**（0.22504 vs 实测 0.29879）与 homogeneity 的**页内自相矛盾**（0.66 vs 0.67）。8 张图已逐张目视核查（含 11×6 的算法对照总图：只有 7 个方法把同心圆分开，DBSCAN/HDBSCAN/OPTICS 在无结构数据上塌成单簇）。聚类的机制（四条几何假设、$k$ 的三来源、指标三性质）见 [[clustering]]、选型与调参见 [[clustering-selection-and-tuning]]。2.5 节 Decomposing signals in components 是本库**第三个无监督产物**类目，也是第一次把「成分」当成一等输出：矩阵分解在同一个 $X\approx UV$ 骨架上，用约束区分模型——PCA 要正交与最大方差、SparsePCA/DictionaryLearning 要 $ℓ_1$ 稀疏、NMF 要非负、FA 要对角噪声、ICA 要独立、LDA 要 Dirichlet 主题。它把前面三条无监督路线补全为「删列（1.13）/ 换坐标（2.2）/ 分组（2.3）/ 分解（2.5）」，并第一次让 `components_` 可以直接读成 eigenface、人脸零件或主题词。结构上它是**接口完整、机制全丢**的样本：4 个内容折叠块（833 词）恰好是 KernelPCA 求解器、LSA 数学、NMF 两个求解器与 LDA 生成过程，约 14 条参考文献也丢了，末尾 6 个脚注还把 NMF 小节重复了 886 词；版本判为 **1.9.1**（1.8→1.9 的唯一正文差异「SVMs」→「kernel approximation」已出现在 L69），另在 1.6.1 实测 20 条（`FastICA(whiten=False)` 忽略 `n_components`、NMF `nndsvd`+`mu` 误差 4.4395 vs `nndsvdar` 1.4714、randomized PCA 反投影差 0.567、SparsePCA `alpha=10` 误差 10.721 等），并发现正文 `split_code`/`transform_method` 与 API 的 `split_sign`/`transform_algorithm` 不同名、`dict_img2` 实际是 MiniBatchKMeans 图；23 张唯一图全部入库，15 张已目视核查。矩阵分解的机制（约束即模型、可辨识性、成本）见 [[matrix-factorization]]，选型与调参见 [[decomposition-selection-and-tuning]]。

2.6 节 Covariance estimation 是本库**第一个不估计模型、只估计二阶结构**的来源（[[covariance-estimation]]）：$\Sigma$ 与 $K=\Sigma^{-1}$ 本身就是目标，下游（LDA/QDA、Mahalanobis、GMM）只是消费者。它把「正则化」从系数空间再推进一层——四个收缩估计器（`EmpiricalCovariance`/`ShrunkCovariance`/`LedoitWolf`/`OAS`）实测是**同一个算子 + 三种 α 来源**：`LedoitWolf`/`OAS` 的 `covariance_` 与 `ShrunkCovariance(shrinkage=α̂)` 逐位相同；α 的目标是 $\Sigma$ 的 MSE，**不是**下游似然（$p=5,n=40$ 时手设 α=0.1 的 held-out NLL 7.267 优于 LW 的 7.295，而 $n=p$ 时经验协方差的 NLL 为 `inf`）。它同时贡献了几个「第一次」：第一次把**精度矩阵当成图**（$K_{ij}=0$ ⇔ 条件独立，见 [[sklearn-covariance]] L79）；第一次出现「两个无监督对象名字相反」——$\Sigma$ 稀疏是边际独立、$K$ 稀疏是条件独立，收缩能压小非对角却不能把它置零，只有 $K$ 上的 L1 能恢复结构；第一次把**四种损失口径的系统性冲突**写成表（held-out NLL / $\Sigma$ 误差 / Mahalanobis 分离度 / 支持集 F1：CV 的 α 的边数比真值多 2.8–6.8 倍，却给出最小的 $\Sigma$ 误差）。它还修正了本库一个旧结论：1.2 节文档说 LDA 的 `shrinkage=1` 终点是「方差对角阵」，而 1.6.1 实测是 $133.3276\,I$（标量乘单位阵）；并且 `shrinkage='auto'` 因内部先标准化而**对特征缩放等变**，手设 float **不等变**（8.9e-15 vs 7.22）——这解决了 [[gaussian-discriminant-analysis]] 原来的待验证假设。该剪藏是本库**正文最完整、损失最集中在文献层**的一份（1,804/1,848 词），但 4 条参考文献与 4 处引用标记全丢、5 个脚注重复了 631 词，版本判为 **1.7.0–1.9.1**，另在 1.6.1 实测 23 条（LW 在 $n=2$ 时 α 恒为 0、MCD 使 Frobenius 误差 9.394→0.313、`support_`≠h 等），5 张图全部目视核查。协方差估计的机制见 [[covariance-estimation]]，选型与调参见 [[covariance-estimation-selection-and-tuning]]。

2.7 节 Novelty and Outlier Detection 是本库**第二个「无监督但任务不是分组」**的来源（[[anomaly-detection]]）：它补上的不是又一个模型族，而是**一个问题的定义**——outlier detection（训练集被污染、异常不能成簇）与 novelty detection（训练集干净、只判新样本）。它把本库已有四个估计器接进同一套契约：`score_samples` 给原始分数、`contamination` 定阈值（落成 `offset_`）、`decision_function = score_samples − offset_`、`predict` 给 ±1；四个估计器的「形状假设」完全不同（高斯椭圆 `EllipticEnvelope`、支持边界 `OneClassSVM`、隔离路径 `IsolationForest`、局部密度比 `LocalOutlierFactor`），而**阈值语义也不同**——IF 的 `'auto'` 是常数 −0.5、LOF 是 −1.5、EE 默认 0.1 且不接受 `'auto'`、OCSVM 根本没有这个参数。因此「同一数据上五个默认输出谁报得多」没有任何意义，这是本节最实用的一条工程结论。实测（1.6.1，25 条）把几条文档断言变成了数字：`contamination` 在 IF/EE 上精确等于 c·n（55/110/220/550）；LOF 对**密集异常簇**的召回只有 **0.03**，而 IF 与 EE 是 1.00（即 L20 那条「异常不能成簇」的硬约束**只对密度比类成立**）；反过来，LOF 把「距密簇 8σ 但全局很近」的点排到 **2/802**，而 EE 排 **802/802**（局部 vs 全局两种不可互换的读法）；`n_neighbors=400` 在 330 个样本上被静默夹到 329 且一个异常都报不出；`nu=0.01` 给出 6.8% 的训练集异常率（不是「≤1% 的泛化概率」）；OCSVM 在 10⁵ 样本上 29.1s vs `SGDOneClassSVM`+Nystroem 的 0.22s。结构上它是**本库损失最小的一份 sklearn 剪藏**：正文 2,441/2,486 词，只丢了 Liu/Ting/Zhou 2008 这一条文献与 2 处引用标记；版本判为 **1.9.1**（剪藏含 1.9 新增的 `contamination`/`offset_` 句，1.8→1.9 正文 diff 只有这一处；`/stable/` 与 `/1.9/` 字节相同）。异常检测的机制（四种形状假设、`offset_` 的四种语义、归纳/传导断层、15 条失效模式）见 [[anomaly-detection]]，选型与调参见 [[outlier-detection-selection-and-tuning]]；它也把 [[nearest-neighbors]]（LOF 是 kNN 图的密度比消费方式）、[[ensembles]]（`IsolationForest` 是 bagging 骨架 + 路径长度聚合）、[[support-vector-machines]]（`OneClassSVM` 复用同一个 ν）与 [[covariance-estimation]]（`EllipticEnvelope` = MCD + 阈值）四页各自向前推了一步。

3.1 节 Cross-validation 是本库**第一个方法学章节**（[[cross-validation]]）：它不引入新模型、不估计新对象，而是回答「前面二十个来源都在用的那个分数是怎么估出来的」。三种调用式对应三种产品——`cross_val_score` 给分数数组、`cross_validate` 给分数加成本与折内模型、`cross_val_predict` 给**折外预测**（并被官方明确判为不适合当泛化误差的度量）；九族 splitter 不是九种写法，而是五组关于「样本为何不独立」的假设（i.i.d. / 类比例 / 组独立 / 时间顺序 / 外部给定），选错不是噪声变大而是在回答另一个问题。它同时贡献了本库几个「第一次」：第一次量化「排序 + 不洗牌」的后果（有序标签上 `KFold` 四折准确率全 **0.0**，而 `StratifiedKFold` 给 `[0.3,0.3,0.4,0.1]`）、第一次把「失败折」的沉默形态写清（某折训练集单类 → 分数变 `nan`，因为 `error_score` 默认 `np.nan`）、第一次发现**官方自己承认分层会压小折间方差**（L361–L365，而这正是 [[leaderboard-vs-cv]] 当作噪声底的量）、第一次把乐观偏差量到两个端点（breast cancer +0.0000 vs 80 样本 × 1500 纯噪声 +0.0500）、以及第一次看到同一个 API 的两条路给出**不同分数**（`cv=5` 在分类器上是 `StratifiedKFold`，与 `cv=KFold(5)` 在 iris 上是 0.98 vs 0.94）。结构上它丢了 **4 个 `<details>` 折叠块（442 词）**，恰好是「held-out 数据上的预处理」全部散文（只剩两段代码，而这两段代码正是本库 0.508→0.900 泄漏实测的出处）、`StratifiedGroupKFold` 的 `Implementation notes`（洗牌为何只在同类分布组之间发生——实测单类组上开洗牌使类比例极差从 0.064 恶化到 0.375）、主 References 的 6 条（含 Kohavi、Rao et al.）与置换检验的 Ojala & Garriga 2010；另有两处页内链接文字丢成「a.」，使「何时不该用 i.i.d. 切分器」那两个关键短语消失。版本判为 **1.7.0–1.9.1**（133 条句子探针 101/122/122/122，1.7→1.8→1.9 正文无 diff，`/stable/` 与 `/1.9/` 字节相同），并在 1.6.1 实测 24 条（`KFold(n)` ≡ `LeaveOneOut`、`RepeatedKFold(5,3)` 的 std 反而比单次 5 折更大、`cross_val_predict` 的 R² 折均值 0.2273 vs 池化 0.8407、置换检验 50 次的下界 $p=0.0196$ 等）；10 张图全部入库并逐张目视核查。机制与失效模式见 [[cross-validation]]，落地流程（五个准入问题、嵌套判据、报告六项、18 条坑）见 [[cross-validation-design-and-tuning]]，它给 [[leaderboard-vs-cv]] 补上了「本地 CV」这一列的内部结构。

3.2 节 Tuning the hyper-parameters 是本库**第二个方法学章节**（[[hyperparameter-search]]），也是损失比例第二高的 sklearn 剪藏：它不引入新模型，只回答「评估协议定死之后，$m$ 个候选、每个要 $k$ 次拟合，预算怎么分」。三种工具因此不是三个 API，而是**三条预算曲线**——穷举按维数指数膨胀、采样把预算与维数解耦（代价是分辨率要不均匀，实测 `uniform(0.001, 1000)` 采 100 次给出 `best alpha` = 4.696，而真最优在 1e-3 附近）、逐次减半用「资源递增 + 每轮淘汰」换壁钟。本机实测（1.6.1，30 余条）改写了四条常识：① `RandomizedSearchCV` 在**所有参数都是列表**时是**不放回采样**，`n_iter` 被静默夹到笛卡尔积大小（要 20 次只跑 5 行）——「预算与参数个数无关」只在分布形态下成立；② `refit` 的默认值是 `True` 而用户指南说 `None`（多指标 + 默认 `refit` 直接 `ValueError`），`refit=callable` 时 `best_score_` 干脆不存在，`refit=False` 时 `predict` 抛的是 `AttributeError` 而非 `NotFittedError`；③ `error_score=np.nan` 只覆盖「部分失败」，**全部失败抛 `ValueError`**、**refit 阶段永远抛错**，所以「搜索跑完了」推不出「模型能训练」；④ **逐次减半的拟合次数永远不少于网格**（8 候选 41 → 76、3 候选 16 → 26、180 候选 541 → 811），它省的是每次拟合的样本量（180 候选的网格：壁钟 24.58s → 8.62s、样本量约 1/31），代价是**与网格的最优参数 5 个种子 0/5 一致**——它回答的是「在这条资源序列上谁最好」。结构上它丢了 **7 个 `<details>` 里的 3 个整块、另 4 个只剩代码，以及整个 §3.2.5**（正则化路径 / AIC-BIC / OOB 三种「不搜索的选参」，正是引言 L30 那个断句「outlined in.」指向的入口），2 条 halving 文献（Jamieson & Talwalkar 2016、Li et al. Hyperband 2018）与 4 条公式的全部解释也一并消失；官方正文 3,898 词只剩 **1,888 词**。版本判为 **1.7.0–1.9.1**（50 条句子探针非判别性，定版靠 L233 的 1.7 措辞；1.7→1.8 正文 diff 为空；`/stable/` 与 `/1.9/` 字节相同）。机制（三条预算曲线、`best_score_` 是最大值而非估计、失败的三档语义）见 [[hyperparameter-search]]，落地流程（五个准入问题、搜索器判定表、拟合次数算术、七条诊断信号、18 条坑）见 [[hyperparameter-search-and-tuning]]；它给 [[cross-validation]] 补上了「分数被取最大值之后」那一段，也给 [[leaderboard-vs-cv]] 的「代理指标被高频优化」提供了 API 层的具体形态。

3.4 节 Metrics and scoring 是本库**第三个方法学章节**（[[evaluation-metrics]]），但它与前两个方向相反：3.1 问「分数怎么估」、3.2 问「$m$ 个分数怎么比」，3.4 问「**那个分数本身该是谁**」。它不引入新模型，只给出一条两层判据——先声明**目标泛函**（均值/中位数/分位数/众数），再选**严格一致（strictly consistent）**于该泛函的评分函数，并建议训练损失与评估指标用同一个函数。这条判据把本库此前所有「A 比 B 好 0.3%」的读数补上了缺失的前提，也让一个旧困惑变成定理：accuracy 无法评价概率质量，不是因为「太粗糙」，而是因为 0-1 损失对众数只 *consistent* 不 *strictly consistent*（实测：真实 $p=0.3$ 时报告 0.2/0.3/0.4/0.5 的四个预报，log loss 0.6378/**0.6101**/0.6321/0.6931 而准确率**全为 1.0000**）。它同时贡献了本库几个「第一次」：第一次把「三层评分入口」（估计器 `score` / `scoring=` / `metrics` 函数）的返回值与符号摊开（`neg_*` 是 scorer 的私有 `_sign`，每个字符串名还绑定一个响应方法，`roc_auc` 按 `decision_function` → `predict_proba` 的偏好序取）；第一次把「泛函错配反转排名」量成表（同一训练集的三个 HGB 目标：分位数模型在 pinball 0.9 上 0.1401 vs 另两个 0.26，而在 $R^2$ 上是 **−0.1012**）；第一次证明「指标选错」的两个默认值都是错的（`make_scorer(mean_squared_error)` 的 `greater_is_better=True` 让搜索器选出最差 `alpha`，MSE 6290 vs 775；`make_scorer(log_loss)` 三折全 `nan`，必须显式 `response_method='predict_proba'`，而这个默认值在 1.8 从 `'default'` 改成 `'predict'` 也仍然错）。它还补齐了「阈值是模型外第二步」这条通则：`predict` 恒等于 `proba >= 0.5`，同一个逻辑回归在四个阈值下准确率 0.946/0.954/0.802/0.546——这把 [[outlier-detection-selection-and-tuning]] 的「定阈值五步」从特例提升为通则。结构上它是本库**损失比例最高的一份来源**：官方 54 个编号小节只有 4 个进来（18,573 词里约 92% 不在），且保留的四节里仍丢了「评分函数」整列、43 行字符串评分表、`Usage examples` doctest 与 4 条参考文献（Gneiting 2007/2009/2014、Fissler 2022），`sklearn.metrics` 的 40 多个指标函数**没有任何正文**。版本判为 **1.8.0–1.9.1**（唯一判别证据是一条脚注：“with one-hot encoded targets” 1.6/1.7 无、1.8/1.9 有；覆盖区 1.8→1.9 逐句 diff 为空；`/stable/` 与 `/1.9/` 字节相同），并在 1.6.1 实测 18 条（`get_scorer_names()` 56 个名字 vs 文档表 43 行的**双向**不一致、`neg_log_loss`/`roc_auc` 的失败只变 `nan`、`zero_division='warn'` 与 `balanced_accuracy_score` 默认 `adjusted=False` 的两处口径错位等）。指标选择的落地流程见 [[metric-selection-and-thresholding]]。

8.3 节 Preprocessing data 是本库**第一个「对列本身动手」**的来源（[[feature-preprocessing]]）：前面十七个 sklearn 章节都在回答「用哪个模型、怎么拟合、怎么评估」，这一节回答的是**模型看到的那张矩阵长什么样**。它把预处理从一组技巧变成一份**有状态的契约**——16 个变换器里 13 个在 `fit`
