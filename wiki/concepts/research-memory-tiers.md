# 研究记忆分层与知识成熟度分级

长期运行的研究 agent 需要回答两个不同的问题：**谁在什么时候需要哪段信息**（分层），以及**这段信息现在有多可信**（成熟度）。Hyra 2.0 的博客把这两件事拆成显式的三个存储层与三级知识标签（[[hyra-2-0]], section "为升级工具而生的 Harness"，`raw/articles/Hyra 2.0.md:79-85`）。本页先记来源论述，再给综合与假设。

## 来源论述

### 三个存储层

| 层 | 内容 | 生命周期 | 位置 |
| --- | --- | --- | --- |
| 项目状态 | 任务队列、Research Board（想法、实验发现、证据、关键决策） | 项目内 | 队列 + 看板（`raw/articles/Hyra 2.0.md:71`、`:81`） |
| agent 工作记忆 | 每个 agent 的**分层记忆**：当前认识、关键假设、已排除的路线、下一步计划 | 跨会话、随认知更新 | 每个 agent 私有（`raw/articles/Hyra 2.0.md:81`） |
| 共享知识库 Books | 跨任务可复用的经验：做法、理由、适用条件 + 原始证据 | 跨项目、长期 | 团队共享（`raw/articles/Hyra 2.0.md:81-83`） |

「生命周期」列是本库推断：来源只说明每层存什么，未说明保存多久与失效规则。

分层的动力来自成本与并行：来源说单次尝试越昂贵，越有必要留下排查方法、验证流程与自动化检查，避免后续项目重复摸索（`raw/articles/Hyra 2.0.md:79`）；而普通进展由其他 agent 异步阅读、必须处理的问题才走消息通知并要求明确回应，从而不必频繁打断正在工作的 Worker（`raw/articles/Hyra 2.0.md:71`）。

### 三级成熟度

Books 的记录必须写明**做法、理由、适用条件**并附**原始证据**，然后按可信度分级（`raw/articles/Hyra 2.0.md:83`）：

| 级别 | 判定条件 | 允许的用法 |
| --- | --- | --- |
| 观察 | 单次实验发现的现象 | 供后续研究参考 |
| 已验证 | 经过**独立复现** | 作为可靠依据 |
| 约定 | 影响团队行为 | 需**人类确认** |

来源还声明：新证据出现后，已有记录会被修正（同上）。这使 Books 不是只增不改的档案，而是带修订历史的信念集合。

### 从记忆到工具：skill

项目复盘时，可迁移的方法被整理成 **skill**（例如训练模型时积累的经验已成套），skill 本身也被视为 Hyra 2.0 造出的工具，会在使用中继续修改完善；作者把这部分算作「持续学习」（`raw/articles/Hyra 2.0.md:85`）。

## 综合

### 与 Hyra 1.0 经验库的关系

| 维度 | 1.0 的 EB（[[experience-bank]]） | 2.0 的三层 + Books |
| --- | --- | --- |
| 作用域 | 单个任务的历史 solution | 项目内状态、agent 私有认知、跨项目知识 |
| 条目内容 | solution 源码、日志、评分；合成为「灵感」 | 做法/理由/适用条件/原始证据 |
| 可信度 | 无显式分级，靠分数隐含 | 观察 / 已验证 / 约定 |
| 修正机制 | 未描述 | 声明会随新证据修正 |
| 复用形态 | 灵感注入新一轮搜索 | skill（可执行的方法封装） |

（对照 [[hyra-1-0]]、[[hyra-2-0]]；表格为本库整理。）

关键差异是**评分不再是唯一的可信度信号**。在 1.0 里，高分 solution 天然是「灵感」的优质来源；在 2.0 里，一个现象要被当作依据，必须经过独立复现，这与 reward hacking 的现实风险直接对应（见 [[evaluator-design-and-reward-hacking]]）。

### 为什么「分层」在工程上必要

- **写入口径不同**：看板记录「发生了什么」，工作记忆记录「我当前相信什么」，Books 记录「别人可以怎样复用」。三者混写会导致要么记录过细无法阅读，要么丢失可复用条件。
- **失效速度不同**：项目状态随项目结束即失效；agent 记忆随认知更新频繁重写；Books 的条目才值得长期维护并加版本。
- **权限不同**：约定级条目需要人类确认，意味着 Books 至少要有「谁能晋升条目」的权限模型。

### 可迁移的清单（本库建议）

1. 每条知识显式标注**成熟度**，并写清「谁复现过」；没有复现证据的标为观察。
2. 记录必须带**适用条件**，否则跨任务复用会变成误用。
3. 「影响团队行为」的知识（约定、门禁、审批阈值）单列，且必须人工确认。
4. 修订而非覆盖：保留旧结论与推翻它的证据，便于审计。

## 假设（待验证）

- 假设 1：显式成熟度分级能显著降低错误经验的传播，但会增加记录与晋升的人力成本。
- 假设 2：skill 是比「文本经验」更可靠的复用单元，因为可执行、可测试。
- 假设 3：agent 私有分层记忆与共享 Books 之间的边界难维护，容易出现「同一事实两处不一致」。

## 待解问题

- 由谁判定「独立复现」成立？复核者与执行者的隔离如何保证（来源提到 Review Worker 先接触原始证据，但未说明其独立性判定标准，`raw/articles/Hyra 2.0.md:77`）。
- Books 的晋升与降级流程、冲突条目如何合并，均未披露。
- 观察级条目会不会被后续 agent 误当事实使用？有无引用时的强制级别标注？
- skill 的版本、测试与失效机制未说明。
