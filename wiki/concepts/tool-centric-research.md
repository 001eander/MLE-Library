# 工具中心的研究（Tool-Centric Research）

一种把自动化研究的**产出单位**从「答案」换成「工具」的取向：agent 的目标不只是解决眼前的问题，而是产出可被反复调用的模型、工作流或验证程序，使一次投入被后续任务分摊。本页依据腾讯混元 Hyra 2.0 的官方博客表述（[[hyra-2-0]]），并对照同系列 [[hyra-1-0]] 的「解题」取向；属于**来源论述 + 综合**，尚无独立论文支撑。

## 来源论述

### 1. 为什么答案不值钱，工具值钱

- 来源的判断：「刷题抽卡」式的突破固然可贵，但它的成果「并不会自动提升下一次研究的能力，形成智能复利」；而「升级一件工具，所有用到它的下游任务都会随之受益」（[[hyra-2-0]], section "从答案到工具"，`raw/articles/Hyra 2.0.md:40-42`）。
- 工具被定义为「能被人类或 agent 反复使用、帮助完成一类任务的方法与系统」（`raw/articles/Hyra 2.0.md:46`）。

### 2. 两种载体

| 载体 | 形态 | 例子 | 改进方式 |
| --- | --- | --- | --- |
| 符号化工具（symbolic） | 代码、规则、流程 | 搜索算法、验证程序、数据处理管线、研究工作流 | 改写显式步骤即改变能力与效率 |
| 参数化工具（parametric） | 模型权重 | 通用语言模型、蛋白质设计模型 | 通过训练把数据与反馈中的规律存进参数 |

（来源论述，`raw/articles/Hyra 2.0.md:48-49`。）

### 3. 通用性阶梯

来源给出的四级台阶，越往上越通用，但研发周期更长、环境更复杂（`raw/articles/Hyra 2.0.md:53-55`）：

1. 解出一道题 → 得到一个**答案**；
2. 做一套适合这类题的工作流，或训练一个推理更强的模型 → 惠及**无数题**；
3. 一个能自动训练出这种模型的**系统**；
4. 一个能自动做任何任务的系统（AGI）。

来源据此把「加速一个现成模型」判为较易（反馈快），把「端到端做出新模型（设计、实现、部署）」判为更难的台阶，并把 Hyra 2.0 的目标表述为「成为最会创造工具的系统」（[[hyra-2-0]], `raw/articles/Hyra 2.0.md:57`）。

### 4. 经济性论证

来源对「更经济、更可持续」的回答完全建立在**摊销**上：工具研发的前期投入由后续许多任务共同分摊；更快模型降低单次调用开销，更好工作流减少重复探索，沉淀成 skill 的经验让后续任务少走弯路（[[hyra-2-0]], section "回到开头的三个问题"，`raw/articles/Hyra 2.0.md:185`）。

## 综合

### 评价口径的变化

若产出单位是工具，则「这次研究做得好不好」不再由单一分数回答，而要看**下游复用**。来源的三问回答给出了三个可操作判据（本库归纳，`raw/articles/Hyra 2.0.md:183-187`）：

| 判据 | 具体问题 | 可测量的代理指标（本库建议） |
| --- | --- | --- |
| 结果 | 解出了什么 | 任务成功率、刷新纪录数 |
| 遗留 | 为后续留下了什么（工作流/模型/验证方法） | 被后续项目调用的次数、节省的迭代时间 |
| 瓶颈定位 | 这次失败归因于能力、搜索还是验证反馈 | 瓶颈类别的分布与下一轮目标命中率 |

### 工具化的三种「难度」其实来自反馈延迟

来源用「反馈速度快 → 容易」解释为什么加速现有模型易于端到端造新模型（`raw/articles/Hyra 2.0.md:57`）。沿这条线可以统一解释其成果的形态（**综合**）：

- 反馈以秒计（kernel 计时、码距搜索、仿真 rollout）→ agent 可以高频试错，改进集中在搜索与验证效率；
- 反馈以小时到天计（训练、蛋白模型评测）→ 必须靠队列、异步与人工审批组织，改进集中在流程与记忆；
- 反馈以周计或需要人工核验（数学证明、芯片设计、真机）→ 瓶颈从「生成」转向「验证」，因此 2.0 在这类项目上投入了独立复核、形式化验证与精确证明。

### 与「解题范式」的分工

| 维度 | 解题范式（Hyra 1.0） | 工具范式（Hyra 2.0） |
| --- | --- | --- |
| 产出 | 一个更优 solution | 可复用的模型/工作流/验证程序 |
| 循环单位 | 一次运行 | 一个数天到数周的项目 |
| 评估 | 现成或自建评估器 | 证据链 + 独立复核 + 知识成熟度分级 |
| 收益形态 | 单点突破 | 摊销到下游任务 |
| 主要风险 | reward hacking | 归因困难、验证吞吐、真机鸿沟 |

（对照依据 [[hyra-1-0]] 与 [[hyra-2-0]]；表格为本库整理，详见 [[hyra-1-0-vs-2-0]]。）

## 假设（待验证）

- 假设 1：在同等算力下，工具级产出比答案级产出的**长期**收益更高，但在单任务预算下可能更低（前期投入无法回收）。
- 假设 2：工具的可复用性主要由「接口稳定性」而非「性能上限」决定——被复用的往往是接口清晰、能嵌进他人流程的工具。
- 假设 3：反馈延迟是自动化研究难度的主变量，比任务领域的差异更能预测 agent 的成功率。

## 待解问题

- 如何度量「一次研发被下游复用了多少」？来源没有给出任何复用统计（`raw/articles/Hyra 2.0.md:183-185`）。
- 工具升级的收益如何与底层模型换代分离？来源未披露 Hyra 2.0 所用基座模型。
- 当工具本身变强，评估工具的标准是否也需要升级（元评估）？
- 工具化是否会诱导「造工具而不解决问题」——即用可复用性叙事掩盖单点结果不足？
